# PWA Message App

אפליקציית Web (PWA) שמקבלת הודעות ומציגה Push Notifications באייפון, בלי Apple Developer
Program ובלי Xcode. שרת ה-Node.js מגיש גם את דפי ה-PWA וגם את ה-API - הכל ב-deploy אחד ל-Render.

## שלב 1 - יצירת מפתחות VAPID (חד פעמי)
```bash
npm install
node generate-vapid-keys.js
```
יודפסו `VAPID_PUBLIC_KEY` ו-`VAPID_PRIVATE_KEY` - תעתיק אותם ל-`.env`.

## שלב 2 - הרצה מקומית
```bash
cp .env.example .env
# מלא את VAPID_PUBLIC_KEY, VAPID_PRIVATE_KEY, USERS_JSON
npm start
```
פתח `http://localhost:3000` (לב לב: Push דורש HTTPS, אז בדיקה מקומית של Push עצמו לא תעבוד -
זה טוב לבדוק שהשרת עולה ושהעמוד נטען, אבל את ה-Push בודקים אחרי הפריסה).

הדפדפן יציג פרומפט התחברות מובנה (Basic Auth) - הכנס username/password של אחד המשתמשים
שהגדרת ב-`USERS_JSON` (ראו "רב-משתמשים" למטה). אין צורך לערוך שום קובץ בצד הלקוח - שום סוד
לא מוטבע ב-`app.js`.

## שלב 3 - פריסה ל-Render
1. דחוף ל-GitHub.
2. Render → New → Web Service → חבר את הריפו.
3. Environment Variables: `USERS_JSON`, `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_CONTACT_EMAIL`,
   `YEMOT_SYSTEM_NUMBER`, `YEMOT_PASSWORD`.
4. Build Command: `npm install` | Start Command: `npm start`.
5. Render נותן HTTPS אוטומטית - חובה בשביל Push (וגם כדי ש-Basic Auth לא יעבור בטקסט גלוי).

## שלב 4 - התקנה באייפון
1. פתח את כתובת ה-Render בספארי (**חייב Safari**, לא Chrome/אחר) - תתבקש להתחבר עם
   username/password שלך מ-`USERS_JSON` (פרומפט מובנה של הדפדפן, לא חלק מהעמוד).
2. כפתור שיתוף (הריבוע עם החץ למעלה) → **הוסף למסך הבית**.
3. פתח את האפליקציה **ממסך הבית** (לא מהטאב בספארי - Push לא יעבוד מטאב רגיל). ייתכן שתתבקש
   להתחבר שוב בפתיחה הראשונה ממסך הבית - זה תקין.
4. לחץ "אפשר התראות" ואשר את ההרשאה.

## שלב 5 - שליחת הודעה
```bash
curl -X POST https://YOUR-APP.onrender.com/send \
  -u YOUR_USERNAME:YOUR_PASSWORD \
  -H "Content-Type: application/json" \
  -d '{"to":"OTHER_USERNAME","text":"שלום!"}'
```

## רב-משתמשים וצ'אט בין-משתמשים
כל משתמש מוגדר ב-`USERS_JSON` (משתנה סביבה אחד, מערך JSON) עם login נפרד, מספר טלפון
משלו, שלוחת ימות נפרדת לשיחות נכנסות ושלוחת ימות נפרדת לשמיעת הודעות - כולם חולקים את
אותו חשבון ימות (`YEMOT_SYSTEM_NUMBER`/`YEMOT_PASSWORD`) עם שלוחות שונות. כל שני משתמשים
יכולים לשלוח הודעות זה לזה - בין אם דרך האפליקציה, דרך חיוג לימות, או שילוב (משתמש אחד
באפליקציה והשני בטלפון בלבד).

```
USERS_JSON=[
  {"username":"dad","password":"secret1","phone":"0501111111","yemotExtension":"135","yemotReplyExtension":"6"},
  {"username":"mom","password":"secret2","phone":"0502222222","yemotExtension":"136","yemotReplyExtension":"7"}
]
```
- `username`/`password` - login לאפליקציה (Basic Auth). הסיסמה מוצפנת (scrypt) ונשמרת ב-DB
  באתחול השרת, לא בטקסט גלוי.
- `phone` - מספר הטלפון האישי של המשתמש. משמש כ"תיקיית שיחה" בתיבת ימות של הצד השני (ראו
  למטה) - לא חייב להיות מספר אמיתי שעובד, אבל צריך להיות ייחודי לכל משתמש.
- `yemotExtension` - המספר שמשתמשים אחרים מקישים בטונים כדי לבחור בו כנמען כשהם שולחים
  הודעה קולית דרך ימות (ראו "שליחת הודעה קולית" למטה) - **לא** חייב להיות זהה למספר השלוחה
  בפועל בפאנל ימות, אבל הכי פשוט להשתמש באותו מספר כדי לא להתבלבל.
- `yemotReplyExtension` - מספר השלוחה שממנה כל משתמש שומע את ההודעות שנשלחו אליו (חייבת
  להיות שלוחה אמיתית וייחודית לכל משתמש בפאנל ימות, ראו "שמיעת הודעות" למטה).

עדכון `USERS_JSON` ופריסה מחדש (redeploy) מוסיף/מעדכן משתמשים אוטומטית באתחול הבא - אין
צורך בפאנל ניהול או במחיקת המשתמש הקיים.

## שליחת הודעה קולית דרך ימות המשיח
כל משתמש יכול לחייג לשלוחה שלו בימות, לבחור בטונים למי ההודעה מיועדת, ולהקליט אותה -
ההודעה מגיעה לנמען **כטקסט מתומלל בלבד** (ההקלטה עצמה לא נשמרת בשום מקום, רק משמשת רגע
לצורך התמלול ואז נמחקת מהזיכרון), וגם כקובץ TTS בתיבת ימות של הנמען אם הוא רוצה לשמוע
אותה בטלפון (ראו "שמיעת הודעות" למטה).

### איך זה עובד
1. אתה מתקשר לשלוחה שהוגדרה לך בימות (route `/yemot/<username>` - ראו "רב-משתמשים" למעלה).
2. השרת שואל "הקש את מספר השלוחה של מי שברצונך לשלוח לו הודעה" - מקישים את ה-`yemotExtension`
   של הנמען (מוגדר לו ב-`USERS_JSON`) ולאחריו סולמית.
3. השלוחה משמיעה "אחרי הצפצוף הקלט..." ומקליטה עד 2 דקות (לחיצה על # מסיימת).
4. השרת מוריד את ההקלטה מהשרת של ימות (דרך Login+DownloadFile מה-API הרגיל שלהם), שולח
   אותה לתמלול ב-OpenAI, ושומר את הטקסט במסד הנתונים כהודעה בין שני המשתמשים.
5. לנמען נשלח Push (אם יש לו מכשיר רשום) עם הטקסט המתומלל, וגם קובץ TTS מועלה לתיבת ימות
   שלו - כך שהוא יראה את ההודעה באפליקציה **וגם** ישמע אותה אם יתקשר לשלוחה שלו.

### תמלול עם OpenAI (חובה בפועל, בלי זה אין תוכן להודעה)
צריך `OPENAI_API_KEY` (ברירת מחדל: `gpt-4o-mini-transcribe`, כ-0.003$ לדקה).
אם התמלול נכשל מסיבה כלשהי (מפתח חסר, שגיאת רשת), עדיין נשמרת הודעת placeholder
("התקבלה הודעה קולית מ-X, אך התמלול נכשל") - כך לפחות ידע הנמען שנשלחה אליו הודעה, גם אם
לא הצלחתם לדעת מה נאמר בה.

כדי לשנות מודל (למשל לדיוק גבוה יותר): `OPENAI_TRANSCRIBE_MODEL=gpt-4o-transcribe`.

### הגדרה בצד ימות המשיח (פאנל הניהול שלהם)
לכל משתמש (ראו "רב-משתמשים" למעלה):
1. פתח/י שלוחה חדשה, בחר/י סוג שלוחה: **API**.
2. הגדר/י את כתובת ה-URL של השלוחה ל:
   ```
   https://YOUR-APP.onrender.com/yemot/<username>
   ```
   כאשר `<username>` הוא בדיוק ה-`username` שהגדרת לאותו משתמש ב-`USERS_JSON`.
3. שיטת שליחה: ברירת המחדל (GET) מספיקה, אין צורך לשנות ל-POST.

### הגדרת משתני סביבה
צריך את אותם פרטי משתמש (מספר מערכת + סיסמה) שמשתמשים בהם ב-API הרגיל של ימות:
```
YEMOT_SYSTEM_NUMBER=0771234567
YEMOT_PASSWORD=your-yemot-password
```

## שמיעת הודעות דרך ימות המשיח
כל משתמש מתקשר לשלוחת TTS (`yemotReplyExtension`) - שיכולה להיות **משותפת** למספר משתמשים
(למשל כולם עם `yemotReplyExtension: "6"`). הודעות שנשלחות אליו (מהאפליקציה או מימות)
מאוחסנות בתת-תיקייה לפי **מספר הטלפון של הנמען עצמו**
(`ivr2:<yemotReplyExtension>/phone/<הטלפון של הנמען>/<timestamp>.tts`) - כך שכשהוא מתקשר
לשלוחה המשותפת מהטלפון שלו, ימות מזהה אותו לפי Caller ID (`ApiPhone`) ומנחית אותו אוטומטית
על התיקייה עם ההודעות שלו, ולא על התיקייה של משתמש אחר שחולק אותה שלוחה.

### דרישה מקדימה
צריך שלוחה קיימת בימות לכל משתמש, שמוגדרת "להשמיע קובץ קבוע - האחרון שהועלה" (לא שלוחת API) -
זה המספר שמוגדר בשדה `yemotReplyExtension` שלו ב-`USERS_JSON` (ראו "רב-משתמשים" למעלה).
אם אין לך כזו עדיין, תצטרך ליצור/להגדיר אותה בפאנל הניהול של ימות המשיח.

## שמירת נתונים קבועה בשרת של ימות (לא רק בדיסק של Render)
ה-DB המקומי (`messages.db`) יושב בדיסק הרגיל של Render, שנמחק בכל deploy מחדש (אלא אם קונים
Persistent Disk בתשלום). כדי לא לאבד היסטוריית הודעות ורישומי Push בכל deploy, השרת שומר
לכל משתמש גיבוי JSON נפרד של ההודעות וה-subscriptions שלו **בשרת האחסון של ימות המשיח עצמו**
(דרך אותו API של Login+UploadFile/DownloadFile שכבר קיים ל-TTS ולהקלטות - אין תוספת עלות
כי זו פעולת אחסון קבצים רגילה, לא שיחה יוצאת).

### איך זה עובד
1. אחרי כל שינוי אצל משתמש מסוים (הודעה נכנסת/יוצאת, הרשמת/מחיקת מכשיר) - השרת מעלה גיבוי
   JSON מלא של הנתונים שלו לנתיב `ivr2:<yemotReplyExtension של המשתמש>/backup.json`.
2. באתחול השרת (למשל אחרי deploy חדש שמחק את הדיסק) - לכל משתמש שאין לו הודעות מקומיות,
   השרת מוריד את הגיבוי האחרון שלו מימות ומשחזר ממנו. משתמש שכבר יש לו נתונים מקומיים
   (הדיסק לא נמחק) - לא נוגעים בו.
3. הגיבוי הוא "best effort" - אם ההעלאה נכשלת (למשל בעיית רשת), זה רק נרשם ללוג ולא מפיל
   את הבקשה של המשתמש.

### דרישה מקדימה
אותה שלוחת `yemotReplyExtension` שכל משתמש כבר צריך להגדיר בשביל "שליחת תשובה בחזרה" למעלה -
מספיק שהתיקייה שלה קיימת באחסון, אין צורך שהשלוחה "תדע" להשמיע את קובץ ה-JSON הזה (הוא לא
קובץ קול).

## מגבלות לדעת (אמיתיות, לא תיאורטיות)
- Push עובד רק אם האפליקציה מותקנת למסך הבית - לא מטאב ספארי רגיל.
- מדי פעם ה-subscription "נשבר" (למשל אחרי הפעלה מחדש של המכשיר) - השרת מנקה subscriptions
  שפגו אוטומטית (קוד 404/410), אבל תצטרך ללחוץ שוב על "אפשר התראות" כדי להירשם מחדש.
- אין "silent push" - כל הודעה שנשלחת חייבת להיות מוצגת כהתראה, אחרת ה-iOS מבטל את ההרשמה.
- לשימוש אישי (הודעות לא קריטיות) זה מתאים מצוין. אם חשוב לך שכל הודעה תגיע בוודאות,
  עדיין שווה לשקול את הגרסה הנייטיבית (APNs) שבנינו קודם.
