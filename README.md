# PWA Message App

אפליקציית Web (PWA) שמקבלת הודעות ומציגה Push Notifications באייפון, בלי Apple Developer
Program ובלי Xcode. שרת ה-Node.js מגיש גם את דפי ה-PWA וגם את ה-API - הכל ב-deploy אחד ל-Render.

## שלב 1 - יצירת מפתחות VAPID (חד פעמי)
```bash
npm install
node generate-vapid-keys.js
```
יודפסו `VAPID_PUBLIC_KEY` ו-`VAPID_PRIVATE_KEY` - תעתיק אותם ל-`.env`.

## שלב 2 - הרצה מקומית
```bash
cp .env.example .env
# מלא את VAPID_PUBLIC_KEY, VAPID_PRIVATE_KEY, USERS_JSON
npm start
```
פתח `http://localhost:3000` (לב לב: Push דורש HTTPS, אז בדיקה מקומית של Push עצמו לא תעבוד -
זה טוב לבדוק שהשרת עולה ושהעמוד נטען, אבל את ה-Push בודקים אחרי הפריסה).

האפליקציה תציג טופס התחברות משלה (לא פרומפט מובנה של הדפדפן) - הכנס username/password
של אחד המשתמשים שהגדרת ב-`USERS_JSON` (ראו "רב-משתמשים" למטה). הפרטים נשמרים ב-
`localStorage` של הדפדפן/PWA ומצורפים אוטומטית לכל בקשה - אין צורך להתחבר שוב בכל פתיחה.

## שלב 3 - פריסה ל-Render
1. דחוף ל-GitHub.
2. Render → New → Web Service → חבר את הריפו.
3. Environment Variables: `USERS_JSON`, `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_CONTACT_EMAIL`,
   `YEMOT_SYSTEM_NUMBER`, `YEMOT_PASSWORD`.
4. Build Command: `npm install` | Start Command: `npm start`.
5. Render נותן HTTPS אוטומטית - חובה בשביל Push (וגם כדי שהסיסמה לא תעבור בטקסט גלוי).

## שלב 4 - התקנה באייפון
1. פתח את כתובת ה-Render בספארי (**חייב Safari**, לא Chrome/אחר) - תתבקש להתחבר בטופס
   שבתוך העמוד (לא פרומפט מובנה של הדפדפן - ראו "התחברות" למטה למה).
2. כפתור שיתוף (הריבוע עם החץ למעלה) → **הוסף למסך הבית**.
3. פתח את האפליקציה **ממסך הבית** (לא מהטאב בספארי - Push לא יעבוד מטאב רגיל). תצטרך
   להתחבר שוב בפתיחה הראשונה ממסך הבית (זה `localStorage` נפרד מהטאב הרגיל) - אחרי זה
   ההתחברות נשמרת.
4. לחץ "אפשר התראות" ואשר את ההרשאה.

## התחברות
האפליקציה **לא** משתמשת בפרומפט ה-Basic Auth המובנה של הדפדפן - יש לה טופס התחברות משלה
(שם משתמש+סיסמה) שרץ בתוך העמוד ושולח POST ל-`/login`. הסיבה: הפרומפט המובנה לא עובד
באמינות ב-PWA מותקן במסך הבית ב-iOS (standalone) - חלק מהגרסאות פשוט לא מציגות אותו,
ומציגות את גוף התשובה כטקסט גולמי ("נדרשת התחברות") בלי לבקש שם/סיסמה בכלל.

אחרי התחברות מוצלחת, הפרטים נשמרים ב-`localStorage` (כ-base64, אותו פורמט כמו Basic Auth)
ומצורפים אוטומטית כ-header `Authorization` לכל בקשת API מ-`app.js`. אם השרת מחזיר 401
(למשל סיסמה שהשתנתה), האפליקציה מנקה את הפרטים השמורים ומציגה את טופס ההתחברות מחדש.

## שלב 5 - שליחת הודעה
```bash
curl -X POST https://YOUR-APP.onrender.com/send \
  -u YOUR_USERNAME:YOUR_PASSWORD \
  -H "Content-Type: application/json" \
  -d '{"to":"OTHER_USERNAME","text":"שלום!"}'
```

## רב-משתמשים וצ'אט בין-משתמשים
כל משתמש מוגדר ב-`USERS_JSON` (משתנה סביבה אחד, מערך JSON) עם login נפרד ומספר טלפון
משלו - כולם חולקים את אותו חשבון ימות (`YEMOT_SYSTEM_NUMBER`/`YEMOT_PASSWORD`) **ואת אותה
שלוחה אחת בימות** (ראו "שליחת הודעה קולית" למטה - אין צורך בשלוחה נפרדת לכל משתמש). כל
שני משתמשים יכולים לשלוח הודעות זה לזה - בין אם דרך האפליקציה, דרך חיוג לימות, או שילוב
(משתמש אחד באפליקציה והשני בטלפון בלבד).

```
USERS_JSON=[
  {"username":"dad","password":"secret1","phone":"0501111111","label":"דוד","yemotExtension":"1","yemotReplyExtension":"6"},
  {"username":"mom","phone":"0502222222","label":"אמא","yemotExtension":"2","yemotReplyExtension":"6"}
]
```
- `username`/`password` - login לאפליקציה (Basic Auth). `password` אופציונלי - למשתמש
  "טלפון בלבד" שלא נכנס לאפליקציה אפשר להשמיט אותו (נוצרת סיסמה רנדומלית שאף אחד לא מכיר).
  הסיסמה מוצפנת (scrypt) ונשמרת ב-DB באתחול השרת, לא בטקסט גלוי.
- `phone` - מספר הטלפון האישי של המשתמש. משמש כ"תיקיית שיחה" בתיבת ימות שלו (ראו "שמיעת
  הודעות" למטה) - לא חייב להיות מספר אמיתי שעובד, אבל צריך להיות ייחודי לכל משתמש.
- `label` - השם שנשמע בתפריט הטונים המשותף בימות ("לדוד הקש 1, לאמא הקש 2...").
- `yemotExtension` - הקוד שמקישים בטונים בתפריט המשותף - גם כדי לזהות את עצמך כשולח, וגם
  כדי לבחור מישהו כנמען (ראו "שליחת הודעה קולית" למטה) - **לא** שלוחה אמיתית בפאנל ימות,
  רק מספר לתפריט.
- `yemotReplyExtension` - מספר השלוחה האמיתית שממנה שומעים הודעות (ראו "שמיעת הודעות"
  למטה) - יכולה להיות **זהה לכל המשתמשים** (שלוחה אחת משותפת), כי ההפרדה נעשית לפי תיקיית
  הטלפון של כל אחד בתוכה.

עדכון `USERS_JSON` ופריסה מחדש (redeploy) מוסיף/מעדכן משתמשים אוטומטית באתחול הבא - אין
צורך בפאנל ניהול או במחיקת המשתמש הקיים.

## קבוצה
יש קבוצה קבועה אחת בשם "כולם", שכוללת אוטומטית את כל המשתמשים שמוגדרים ב-`USERS_JSON`
(נוצרת/מתעדכנת באתחול השרת - ראו `groups.js`). היא מופיעה ברשימת השיחות באפליקציה (עם
אייקון 👥) ליד אנשי הקשר הרגילים.

הודעה לקבוצה נשלחת ב-**Push וגם ב-TTS** לכל החברים (חוץ מהשולח) - כמו הודעה אישית, אבל
כולם שומעים אותה דרך אותה שלוחה משותפת קבועה (**שלוחה 9**, ראו `DEFAULT_GROUP_YEMOT_EXTENSION`
ב-`groups.js`), ולא דרך השלוחה האישית (6) של כל אחד. **צינתוק לא מופעל** לקבוצה - רק
Push+TTS.

### הגדרה בצד ימות המשיח
צריך ליצור שלוחה **אחת נוספת** (מספר 9), מוגדרת בדיוק כמו שלוחה 6 - "להשמיע קובץ קבוע -
האחרון שהועלה" (לא שלוחת API). בלי זה, ה-TTS הקבוצתי לא יעבוד (רק ה-Push).

הודעות קבוצה נשמרות בטבלה נפרדת (`group_messages`) ו**לא** מגובות לשרת ימות כרגע (בניגוד
להודעות אישיות/subscriptions - ראו "שמירת נתונים קבועה" למטה) - כלומר היסטוריית קבוצה
עלולה להימחק ב-deploy הבא ב-Render אם אין Persistent Disk.

## שליחת הודעה קולית דרך ימות המשיח
כל המשתמשים מתקשרים לאותה שלוחה אחת בימות. השרת מזהה את השולח **אוטומטית לפי מספר
הטלפון שממנו מתקשרים** (`ApiPhone`, מותאם מול שדה `phone` שלו ב-`USERS_JSON`) - אין
צורך להקיש קוד זיהוי עצמי. אחר כך שואל למי לשלוח, בתפריט טונים דינמי שנבנה אוטומטית מכל
המשתמשים ("לדוד הקש 1, לאמא הקש 2..."). ההודעה מגיעה לנמען **כטקסט מתומלל בלבד** (ההקלטה
עצמה לא נשמרת בשום מקום, רק משמשת רגע לצורך התמלול ואז נמחקת מהזיכרון), וגם כקובץ TTS
בתיבת ימות של הנמען אם הוא רוצה לשמוע אותה בטלפון (ראו "שמיעת הודעות" למטה).

### איך זה עובד
1. אתה מתקשר לשלוחה המשותפת (route `/yemot` - ראו "הגדרה בצד ימות המשיח" למטה).
2. השרת מזהה אותך לפי מספר הטלפון שהתקשרת ממנו, מול שדה `phone` ב-`USERS_JSON` - אם המספר
   לא רשום לאף משתמש, השיחה נדחית עם הודעה מתאימה.
3. השרת שואל "למי ברצונך לשלוח הודעה? לדוד הקש 1, לאמא הקש 2..., לכולם הקש 9" - מקישים
   את ה-`yemotExtension` של הנמען היחיד, **או** את הקוד של הקבוצה (ראו "קבוצה" למעלה),
   ולאחריו סולמית.
4. השלוחה משמיעה "אחרי הצפצוף הקלט..." ומקליטה עד 2 דקות (לחיצה על # מסיימת).
5. השרת מוריד את ההקלטה מהשרת של ימות (דרך Login+DownloadFile מה-API הרגיל שלהם), שולח
   אותה לתמלול ב-OpenAI, ושומר את הטקסט במסד הנתונים כהודעה (בין שני משתמשים, או לכל
   חברי הקבוצה אם זו נבחרה).
6. לנמען/ים נשלח Push (אם יש להם מכשיר רשום) עם הטקסט המתומלל, וגם קובץ TTS מועלה לתיבת
   ימות שלהם - כך שיראו את ההודעה באפליקציה **וגם** ישמעו אותה אם יתקשרו לשלוחה המשותפת.

### חשוב - נקודה לבדיקה
שם השדה שמכיל את מספר הטלפון של המתקשר (`ApiPhone`) מבוסס על מוסכמות ידועות של ימות אך
לא מתועד באופן חד-משמעי. אם הזיהוי לא עובד (המערכת אומרת "המספר שלך לא מזוהה" גם למספר
תקין), תבדוק בלוגים של Render (השרת רץ עם `printLog: true`) מה השם המדויק של השדה ותעדכן
ב-`yemot-ivr.js`.

### תמלול עם OpenAI (חובה בפועל, בלי זה אין תוכן להודעה)
צריך `OPENAI_API_KEY` (ברירת מחדל: `gpt-4o-mini-transcribe`, כ-0.003$ לדקה).
אם התמלול נכשל מסיבה כלשהי (מפתח חסר, שגיאת רשת), עדיין נשמרת הודעת placeholder
("התקבלה הודעה קולית מ-X, אך התמלול נכשל") - כך לפחות ידע הנמען שנשלחה אליו הודעה, גם אם
לא הצלחתם לדעת מה נאמר בה.

כדי לשנות מודל (למשל לדיוק גבוה יותר): `OPENAI_TRANSCRIBE_MODEL=gpt-4o-transcribe`.

### הגדרה בצד ימות המשיח (פאנל הניהול שלהם)
פעם אחת בלבד, לכל האפליקציה (לא לכל משתמש):
1. פתח/י שלוחה חדשה, בחר/י סוג שלוחה: **API**.
2. הגדר/י את כתובת ה-URL של השלוחה ל:
   ```
   https://YOUR-APP.onrender.com/yemot
   ```
3. שיטת שליחה: ברירת המחדל (GET) מספיקה, אין צורך לשנות ל-POST.

### הגדרת משתני סביבה
צריך את אותם פרטי משתמש (מספר מערכת + סיסמה) שמשתמשים בהם ב-API הרגיל של ימות:
```
YEMOT_SYSTEM_NUMBER=0771234567
YEMOT_PASSWORD=your-yemot-password
```

## שמיעת הודעות דרך ימות המשיח
כל משתמש מתקשר לשלוחת TTS (`yemotReplyExtension`) - שיכולה להיות **משותפת** למספר משתמשים
(למשל כולם עם `yemotReplyExtension: "6"`). הודעות שנשלחות אליו (מהאפליקציה או מימות)
מאוחסנות בתת-תיקייה לפי **מספר הטלפון של הנמען עצמו**
(`ivr2:<yemotReplyExtension>/phone/<הטלפון של הנמען>/`, עם מספור אוטומטי של ימות - ראו
[freeivr.co.il](https://f2.freeivr.co.il/topic/9590) - כך שתמיד מושמעת ההודעה האחרונה
בלי סיכון להתנגשות שמות) - כך שכשהוא מתקשר
לשלוחה המשותפת מהטלפון שלו, ימות מזהה אותו לפי Caller ID (`ApiPhone`) ומנחית אותו אוטומטית
על התיקייה עם ההודעות שלו, ולא על התיקייה של משתמש אחר שחולק אותה שלוחה.

### דרישה מקדימה
צריך שלוחה קיימת בימות לכל משתמש, שמוגדרת "להשמיע קובץ קבוע - האחרון שהועלה" (לא שלוחת API) -
זה המספר שמוגדר בשדה `yemotReplyExtension` שלו ב-`USERS_JSON` (ראו "רב-משתמשים" למעלה).
אם אין לך כזו עדיין, תצטרך ליצור/להגדיר אותה בפאנל הניהול של ימות המשיח.

## צינתוק (שיחה יוצאת אוטומטית) כשמגיעה הודעה חדשה
בנוסף ל-Push ולתיבת ה-TTS, אפשר להגדיר שכל משתמש יקבל **שיחה יוצאת אוטומטית** ("צינתוק")
ברגע שמגיעה לו הודעה חדשה - גם אם היא נשלחה מהאפליקציה (לא רק דרך שיחה בימות). זה נעשה
דרך ה-API הרשמי `RunTzintuk` של ימות (ראו
[freeivr.co.il](https://f2.freeivr.co.il/topic/14130) ו-[mitmachim.top](https://mitmachim.top/topic/28633)) -
**שימו לב: בניגוד לשאר הפעולות במסמך הזה, לצינתוק יש עלות קטנה לכל שיחה** (לפי המקורות
שמצאתי - חלק מיחידה, לא בהכרח 0).

### הרשמה עצמית - אין צורך ביצירה ידנית של שלוחה לכל משתמש
במקום ליצור שלוחת `tzintuk` בפאנל ימות בנפרד לכל משתמש, השרת עושה את זה **אוטומטית**:
כשמשתמש מתקשר בפעם הראשונה לשלוחת ההרשמה (route `/yemot/tzintuk`), השרת מזהה אותו לפי
מספר הטלפון, יוצר לו שלוחת `tzintuk` אישית חדשה (כותב קובץ `ext.ini` ישירות דרך
`UploadFile`, ראו `provisionTzintukExtension` ב-`yemot-api.js`), שומר את מספר הרשימה
שלה ב-`tzintuk_list` בבסיס הנתונים, ומעביר את השיחה החיה לשלוחה החדשה (`call.go_to_folder`)
כדי שימות עצמה תציג לו את תפריט ה"הוספת המספר שלי לרשימה". בפעמים הבאות (לאחר שהשלוחה
כבר קיימת), השיחה פשוט מועברת אליה ישירות.

### דרישה מקדימה - חובה, בלי זה לא יעבוד
1. ליצור בפאנל ימות **שלוחת API אחת בלבד** (לא לכל משתמש) שמצביעה ל:
   ```
   https://YOUR-APP.onrender.com/yemot/tzintuk
   ```
2. **כל משתמש שרוצה לקבל צינתוקים חייב להתקשר לשלוחה הזו פעם אחת** - השרת ידאג ליצור לו
   הכל אוטומטית ולהעביר אותו לתפריט ההרשמה עצמו.

תוכן ה-`ext.ini` שנכתב אוטומטית לכל משתמש (מאומת ע"י המשתמש כתקין - אין צורך ב-
`tzintuk_admin`/`run_tzintuk_automat`, כי מפעילים את הצינתוק ב-API מפורש ולא באוטומט):
```
type=tzintuk
list_tzintuk=<מספר ייחודי, נגזר מ-ID של המשתמש>
```

### איך זה עובד בקוד
אחרי שהודעה נמסרת בהצלחה (`chat.js`), אם לנמען יש `tzintukList` - השרת קורא ל:
```
https://www.call2all.co.il/ym/api/RunTzintuk?token=<מספר מערכת>:<סיסמה>&phones=tzl:<tzintukList>
```
זו קריאת HTTP רגילה מהשרת (לא דורשת שיחה חיה) - ולכן עובדת גם כשההודעה נשלחה מהאפליקציה.
אם הקריאה נכשלת, זה רק נרשם ללוג (לא מפיל את שמירת/שליחת ההודעה עצמה).

### לא מתועד רשמית - כדאי לבדוק בשיחת בדיקה
לא מצאתי תיעוד רשמי חד-משמעי (רק אשכולות פורום) - העלות המדויקת ופרטים קטנים (כמו הפורמט
המדויק של `phones=tzl:`) לא מאומתים ב-100%. מומלץ לבדוק עם משתמש אחד בפועל לפני שסומכים על
זה לכולם.

## שמירת נתונים קבועה בשרת של ימות (לא רק בדיסק של Render)
ה-DB המקומי (`messages.db`) יושב בדיסק הרגיל של Render, שנמחק בכל deploy מחדש (אלא אם קונים
Persistent Disk בתשלום). כדי לא לאבד היסטוריית הודעות ורישומי Push בכל deploy, השרת שומר
לכל משתמש גיבוי JSON נפרד של ההודעות וה-subscriptions שלו **בשרת האחסון של ימות המשיח עצמו**
(דרך אותו API של Login+UploadFile/DownloadFile שכבר קיים ל-TTS ולהקלטות - אין תוספת עלות
כי זו פעולת אחסון קבצים רגילה, לא שיחה יוצאת).

### איך זה עובד
1. אחרי כל שינוי אצל משתמש מסוים (הודעה נכנסת/יוצאת, הרשמת/מחיקת מכשיר) - השרת מעלה גיבוי
   JSON מלא של הנתונים שלו לנתיב `ivr2:<yemotReplyExtension>/Phone/<הטלפון של המשתמש>/backup.json`
   (תת-תיקייה לפי הטלפון של המשתמש עצמו - חובה כי כמה משתמשים חולקים אותה שלוחה, אז נתיב
   בלי הטלפון היה גורם לכולם לדרוס את אותו קובץ).
2. באתחול השרת (למשל אחרי deploy חדש שמחק את הדיסק) - לכל משתמש שאין לו הודעות מקומיות,
   השרת מוריד את הגיבוי האחרון שלו מימות ומשחזר ממנו. משתמש שכבר יש לו נתונים מקומיים
   (הדיסק לא נמחק) - לא נוגעים בו. ההודעות נשמרות בגיבוי לפי username של השולח/נמען (לא
   ה-id הפנימי שלהם ב-DB) כדי שהשחזור יעבוד גם כשה-id-ים לא זהים בין מופעים שונים (ראו
   "מירור מקומי" למטה).
3. הגיבוי הוא "best effort" - אם ההעלאה נכשלת (למשל בעיית רשת), זה רק נרשם ללוג ולא מפיל
   את הבקשה של המשתמש.

### דרישה מקדימה
אותה שלוחת `yemotReplyExtension` שכל משתמש כבר צריך להגדיר בשביל "שליחת תשובה בחזרה" למעלה -
מספיק שהתיקייה שלה קיימת באחסון, אין צורך שהשלוחה "תדע" להשמיע את קובץ ה-JSON הזה (הוא לא
קובץ קול).

### מירור מקומי (מריצים את המערכת גם על מחשב אחר, במקביל ל-Render)
אפשר להריץ את אותו קוד גם על שרת/מחשב מקומי, רק כדי לצפות בכל הצ'אטים - בלי שהוא משמש בפועל
לשליחה/קבלה (שיחות מימות ממשיכות להגיע ל-Render, לא למחשב המקומי). כדי להפעיל:

1. הרץ אותו `.env` (אותו `USERS_JSON`, אותם פרטי חשבון ימות) על המחשב המקומי.
2. הוסף `LOCAL_MIRROR=true` ל-`.env` המקומי (השאר ריק/`false` ב-Render עצמו).
3. `npm start` - השרת המקומי ימשוך את הגיבויים מימות באתחול, ואז ימשיך לבדוק כל דקה אם
   יש הודעות חדשות (שנוצרו במופע האמיתי ב-Render) ויוסיף אותן ל-DB המקומי.

הערות:
- הסנכרון הוא חד-כיווני (Render/ימות → מחשב מקומי) ומזהה כפילויות לפי תוכן ההודעה, אז בטוח
  להריץ אותו שוב ושוב בלי ליצור העתקים כפולים.
- הודעות קבוצה לא מגובות לימות כרגע (רק הודעות אישיות) - אז לא יופיעו במירור המקומי.
- מומלץ לא לשלוח הודעות בפועל מהמופע המקומי במקביל להשתמש ב-Render - הן לא יסתנכרנו חזרה
  ועלולות ליצור מצב מבלבל של שני "עדכני אמת" נפרדים.

## מגבלות לדעת (אמיתיות, לא תיאורטיות)
- Push עובד רק אם האפליקציה מותקנת למסך הבית - לא מטאב ספארי רגיל.
- מדי פעם ה-subscription "נשבר" (למשל אחרי הפעלה מחדש של המכשיר) - השרת מנקה subscriptions
  שפגו אוטומטית (קוד 404/410), אבל תצטרך ללחוץ שוב על "אפשר התראות" כדי להירשם מחדש.
- אין "silent push" - כל הודעה שנשלחת חייבת להיות מוצגת כהתראה, אחרת ה-iOS מבטל את ההרשמה.
- לשימוש אישי (הודעות לא קריטיות) זה מתאים מצוין. אם חשוב לך שכל הודעה תגיע בוודאות,
  עדיין שווה לשקול את הגרסה הנייטיבית (APNs) שבנינו קודם.
